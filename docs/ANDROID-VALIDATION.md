# Android 真机验证

验证设备：荣耀 GT（AMG-AN00），Android 16 / API 36。应用为 arm64，target SDK 35、min SDK 28。测试使用项目签名的本地开发 APK，完整构建命令为 `go run ./cmd/android`。

## 已验证

- 用户指定目录完整复制到手机 `Music/Woodwind/music-dl`：853 个文件、7,963,158,132 字节。电脑原文件未修改。
- 经系统目录选择器授权后导入应用存储，索引最终为 291 首歌曲；源文件包括 279 个 FLAC 和 12 个 MP3。播放验证使用实际曲库中的歌曲，并非仅以测试音替代。
- 播放、暂停、恢复和拖动跳转；实际界面显示了推进的进度与正确总时长。更新应用后曲库和暂停位置保留。
- 定向连接 `Woodwind Music` 媒体会话，验证播放、暂停、下一首与上一首，歌曲元数据随切歌更新。测试中观察到自动进入下一首。
- `mediaPlayback` 前台服务正常启动，系统记录 `isForeground=true`、服务类型 `0x00000002`，通知类别为 `transport`，含媒体会话及四个操作。荣耀通知中心显示当前歌曲、封面与媒体按钮。
- 返回桌面后仍正常播放，系统媒体控制能暂停并把实际进度同步回应用。
- 关闭屏幕后，系统进入 `Dozing`，应用的播放唤醒锁仍持续持有；定向暂停得到实际位置 `94,944 ms`，暂停后无活动的播放唤醒锁。
- 291 首的播放队列和暂停位置已保存，测试结束时停止测试播放，未修改系统音量或全局电池设置。
- 完整 `go test ./...` 通过；APK 经 `apksigner verify` 与 16 KiB 页面对齐检查通过。

## 真机中修正的问题

- Android 不应带入桌面 Linux 的 PulseAudio/ALSA 输出依赖。
- Android 11+ 要求 APK 的 `resources.arsc` 不压缩并按四字节对齐。
- 文档目录读取跨越 Go/Java 进程边界；导入改为复用 1 MiB 缓冲，避免默认 32 KiB 读取造成大量 provider 往返。
- 媒体节点与界面置于同一稳定根视图；播放器的时钟计时器归属应用作用域，避免播放按钮重绘时取消计时器而冻结界面时间。
- 已完成的 MediaPlayer 不能只靠 seek 保证重新播放，单曲循环会重新打开当前歌曲。

## 验证范围

实际蓝牙设备、真实来电中断和整夜后台运行没有在本次设备测试中覆盖。焦点中断与恢复的 Go 桥接有自动化测试。系统强制停止应用、设备重启以及厂商主动终止进程不属于持续播放保证。

开发工具保存在项目忽略的 `.tools/android/`，无需全局安装。此 Mac 上最新版 ADB 曾崩溃，bootstrap 固定采用官方 platform-tools 35.0.2。
