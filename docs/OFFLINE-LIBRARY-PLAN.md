# 已存音乐：自动缓存与保留离线功能规划

状态：已按阶段实施，设备行为待人工验收。日期：2026-11-17。

实际入口、存储和使用限制见[已存音乐说明](OFFLINE-MUSIC.md)。歌词随版本化歌曲记录保存，任务集中保存在 `tasks.json`；浏览索引由记录重建，无需单独维护可损坏的索引文件。

## 1. 目标与承诺

将插件歌曲已经保存到本机的内容整理为应用自己管理的音乐资料库，提供固定的「已存音乐」入口。自动缓存、保留离线都可以直接查看、搜索、加入队列和播放，不依赖当前选中的插件，也不要求原插件仍然安装。

两类歌曲使用同一套文件、资料和播放能力，区别在于保存期限：自动缓存可以按空间规则淘汰；保留离线由用户主动保存，不被自动清理。

保证适用于已经成功取得并完整保存、当前平台能够解码的音频。尚未下载完整的资源、只能由外部设备播放的来源、直播或必须由原服务持续授权才能解码的资源，不能标记为可独立离线播放。已取得的试听片段也不能标记为完整歌曲。

## 2. 实施前的情况与改动原因

- `internal/player/cache.go` 只保存音频与 `music.Stream` 信息，没有独立的可浏览歌曲目录，也不保存完整歌曲资料、歌词和封面图片。
- 现有文件名由音乐源 ID、歌曲 ID 的哈希及音质组成，无法从文件名反推出歌名或原始歌曲 ID。
- 桌面播放器在查缓存前要求音乐源存在；安卓原生播放链路直接向音乐源请求播放地址，没有使用桌面音频缓存。
- `removePlugin` 在移除当前歌曲所属插件时清空整个播放队列。
- 歌词通过插件重新请求；封面主要通过网址加载。音频缓存命中并不代表这些资料可以离线显示。
- 桌面歌曲菜单在找不到插件时提前返回，本地操作也随之消失。
- 现有本地文件歌单存储本地歌曲 ID，不能直接拿来承载多插件歌曲而不改身份模型。

因此需要同时改造存储、资源解析、播放、插件移除、导航和菜单，不能只在缓存目录增加歌词文件。

## 3. 产品入口与浏览

### 固定入口

- 桌面侧栏增加「已存音乐」，位于应用自身导航区域，始终可见，不随音乐源切换而消失。
- 手机「音乐库」顶部增加「已存音乐」，同样独立于当前音乐源和登录状态。
- 进入该页面不切换线上音乐源，也不请求任何插件；返回时保留原音乐源页面。
- 不要求用户先在音乐源选择器里切换到“本地文件”。原有本地文件导入流程保留，已存音乐不重复扫描用户原始音乐目录。

### 页面内容

- 顶部分组：「全部」「保留离线」「自动缓存」。每首歌曲只归入一种保存方式；保留离线优先。
- 提供本页搜索，按歌名、歌手、专辑查找；支持按来源、实际音质、资料是否齐全筛选。
- 支持按最近保存、最近播放、歌名、歌手、占用空间排序。
- 支持歌曲、专辑、歌手视图。专辑和歌手页只整理本机已存歌曲，显示“本机已存 N 首”，不暗示已保存完整专辑，也不请求原插件。
- 默认按来源与原始专辑/歌手 ID 区分同名实体，缺 ID 时采用保守分组；不同插件的同名歌、翻唱、现场版不自动合并。
- 列表显示封面、歌名、歌手、保存方式、实际音质，来源和占用空间可在副信息或详情查看。
- 来源显示保存时的名称快照。插件已移除时仍可显示“酷狗概念版 · 插件已移除”。
- 页面提供播放全部、随机播放、加入队列、多选保留离线、取消保留、移除本地副本。
- “下载任务”作为独立的页面操作入口，展示排队、进度、失败与等待状态，不混入可播放歌曲数量。

### 本地操作与线上操作

播放、队列、歌曲信息、复制标题、保留离线和文件管理不依赖插件。评论、线上收藏、线上歌单写入、打开在线专辑等操作仍依赖原插件，只有来源可用时才提供。

本机专辑/歌手页与线上详情入口明确区分。第一版不额外新增一套跨来源自建歌单；该能力后续应采用完整的本地歌曲引用，不能复用只有来源内 ID 的旧存储方式。

## 4. 自动缓存与保留离线规则

| 行为 | 自动缓存 | 保留离线 |
| --- | --- | --- |
| 产生方式 | 在线播放或下一首预取，完整下载后入库 | 用户主动选择歌曲或批量保存 |
| 独立浏览、搜索和播放 | 支持 | 支持 |
| 保存歌曲资料、封面和歌词 | 支持 | 支持 |
| 退出账号、切换或移除插件 | 保留 | 保留 |
| 超过自动缓存上限 | 按最近播放时间淘汰 | 不淘汰 |
| 清空自动缓存 | 删除 | 保留 |
| 关闭自动缓存 | 停止新增自动缓存；不立即删除已有内容 | 不受影响 |
| 用户删除本地副本 | 删除对应本机内容 | 明确提示后删除对应本机内容 |

现有 2 GB 默认值继续用于自动缓存容量。保留离线没有自动淘汰上限，单独显示占用空间，并在新任务空间不足时停止任务、提示释放空间，绝不通过删除其他保留离线歌曲解决。

缓存开关与容量拆开。设置中的“关闭”不再通过把所有存储限额设成零而立即清空；已有容量为零的配置迁移为“自动缓存关闭”。清空是独立操作。

### 保存方式转换

- 完整自动缓存选择“保留离线”：原文件立即获得保护，不复制、不重新下载；缺失资料可以后台补充。
- 尚在下载的歌曲选择“保留离线”：复用同一个下载任务，将任务目标改为保留离线。
- 取消保留：转为自动缓存，保留文件，但提示之后可能被空间清理。转换后不在当前交互中立即淘汰该歌曲；若超限，先清其他可淘汰内容，剩余超额等待后续安全清理。
- “移除本地副本”与“取消保留离线”是不同操作，文案直接说明结果。
- 将自动缓存转换为保留离线时，默认保留当前实际音质。用户可另选“以无损保留”，产生升级任务。

保存方式以音频版本为单位记录。同曲已有自动缓存高音质、用户另存无损时，升级中的失败不会损坏旧版本；一首歌只显示一条，详情列出实际拥有的音质。自动缓存清理不能删掉任何受保护版本，也不能删除受其引用的歌词、封面和歌曲资料。

## 5. 每首歌曲保存什么

### 必备资料

- 独立本地记录 ID，及原音乐源 ID、原歌曲 ID；来源名称快照。
- 歌名、歌手列表、专辑名、时长及已有的专辑/歌手 ID。
- 音频的相对路径、真实格式、实际音质、码率、字节数、完整性信息。
- 保存方式、创建时间、最近播放时间、记录格式版本。
- 文件与来源信息均由应用保存，不依赖插件的数据目录。

本地记录 ID 与来源歌曲身份分开。原插件移除时只改变来源可用性，不改歌曲身份，也不丢失本地队列引用。不同来源歌曲不凭歌名合并。

### 封面

保存图片字节，并生成应用需要的显示版本；离线展示使用本地图片路径。不同歌曲共用的相同封面可以按内容去重，只有最后一个引用消失时才能清理。

封面下载应在来源可用时完成必要鉴权；本地展示不依赖原网址或凭据。只保存恢复资料所需的安全字段，不把令牌、Cookie、鉴权头或带凭据的临时链接写进离线记录。

### 歌词

保存插件返回的 `music.Lyrics` 内容，包括 LRC、翻译、逐行及逐字时间数据。沿用现有歌词解析显示逻辑，保留原始与标准化数据所需的版本信息，避免统一导出成普通 LRC 后丢失逐字效果。

### 资料不完整

分别记录“已保存”“来源未提供”“暂时获取失败”“待补充”。无歌词、无封面不等于下载失败，也不阻止音频播放。

只有音频完整且本地资料记录成功写入，才能显示“已缓存”或“已保留离线”。旁边可以补充显示“缺少歌词/封面”；“资料齐全”是独立状态。

读取缓存资料时立即展示，不等待网络。来源可用时允许用户主动补充资料；后台补充限速并对失败退避，确定未提供的资源不在每次播放时重试。新的失败不能覆盖已经保存的有效资料。

第一版不要求改写 MP3/FLAC 的内嵌标签，独立资料文件已能满足应用内播放。将来如提供导出，再设计标签、LRC 和封面导出。

## 6. 独立播放与插件生命周期

### 统一资源解析顺序

1. 根据本地记录 ID或完整的来源歌曲身份查找可用本地音频，读取本地歌曲资料、封面和歌词。
2. 找到可播放版本后直接播放，不因插件不存在、禁用、账号退出或会员变化而请求原插件。
3. 没有本地音频时，只有普通线上播放才尝试原插件；“已存音乐”发起的播放保持本地模式，不自动转为联网下载。
4. 原插件不存在且没有本地音频时，明确提示“本地文件不可用，原插件已移除”。

播放器和菜单都不能以 `src == nil` 为由在本地查找之前直接返回。播放队列和会话需保存本地记录引用、来源身份和播放模式；重启恢复后仍遵循相同规则。

从已存音乐播放时关闭线上下一首预取、插件播放历史上报和动态电台补歌。记录本机最近播放，系统媒体信息、封面和歌词只从本地资料提供，完全断网也能完成播放操作。

普通线上页面命中本地音频时，歌词/封面也优先使用本地版本。插件上报等线上行为不应成为播放成功的前提。

### 音质规则

- 默认优先选择符合所选音质的本地版本；没有时使用已有的可播放版本，并展示实际音质。
- “已存音乐”永不为了满足全局无损设置而自动发起联网请求。
- 获取更高音质是显式的升级操作。升级成功、校验并切换记录前保留旧版；失败继续使用旧版。
- 插件返回的实际音质低于目标时，如实标注“已保存高品质，未取得无损”，不能显示为无损保存成功。
- 未报告实际音质时显示“音质未知”，不将请求的音质伪装为已确认结果。

### 切换插件

不改变当前歌曲、队列、已存音乐筛选或本地任务身份。下载任务绑定原来源，界面切换不将后续请求发到新选中的插件。异步结果按任务身份检查，防止串源。

### 移除或禁用插件

- 保存完整的本地记录、来源名称、音频、封面和歌词。
- 移除插件时不再无条件清空整个播放队列。
- 正在从完整本地文件播放的歌曲继续播放，队列内其余可用本地歌曲继续可选。
- 原插件专属的动态补歌、未完成解析和未完成下载任务停止或转为等待来源可用；不能把半成品标为已存。
- 队列内尚未保存的歌曲保留可理解的不可用状态；自动下一首可跳过，用户直接点击时说明原因。
- 卸载对话框说明本地已存歌曲保留，歌曲删除在已存音乐中单独管理。
- 同 ID 插件重新安装后可重新启用在线能力；本地歌曲不用重新下载。来源协议或歌曲 ID 已变化时不能猜测关联。

## 7. 下载任务与状态

保留离线支持单曲、选中歌曲、当前专辑或歌单批量操作。批量任务使用点击当时的歌曲列表快照，不后台持续同步线上歌单，也不触发收藏或修改线上歌单。

任务流程：排队 → 获取资源 → 下载音频 → 验证与入库 → 已保留；歌词、封面补充另有进度，不阻塞音频成功。等待登录、等待插件、等待网络、空间不足、失败和已取消分别展示原因。

- 初始设置采用有限并发，例如两个音频任务，播放请求优先；歌词、封面任务也设独立的小并发与大小限制。
- 同一来源、歌曲、目标音质的播放、预取和保留请求复用任务，避免重复下载。最终按实际音质归档。
- 取消某个任务的保留意图，不得中断仍在使用该下载的播放器；下载资源按使用者管理生命周期。
- 暂停不代表一定具备断点续传。仅在服务支持范围请求且能确认资源一致时续传，否则重新获取地址并重下，不能拼接不同版本。
- 重启后恢复任务列表；已完成内容无需重新鉴权，未完成任务重新检查来源和资源。
- 关闭应用不承诺继续下载。安卓第一版明确应用退出或被系统终止后任务暂停，下次启动恢复；进程存活时的后台任务能力按平台机制接入并验收，不以正在播放服务等同于永久下载服务。
- 本地文件来源已有原始文件，不自动再缓存一份；远程控制型插件、直播以及无法输出独立音频文件的资源显示不支持保留离线及原因。

## 8. 空间、删除与一致性

设置显示自动缓存使用量与上限、保留离线使用量、总实际占用，提供自动缓存开关、容量设置、清空自动缓存、进入已存音乐管理。

- 自动缓存按最近实际播放时间清理；预取和补充资料不伪装成用户最近播放。
- 总实际占用按物理文件统计，封面等共享文件只计一次；同时区分任务临时占用。保留离线引用的共享资料随离线内容保留。
- 只淘汰可淘汰版本，不越过保留保护；当前播放和下一首已打开的本地资源持有使用引用。
- 用户删除正在播放的副本时先从列表撤下，物理文件延迟到播放器释放后删除，避免 Windows 删除打开文件失败或跨平台中断。
- 文件先写临时位置，完整验证后原子发布记录；不能存在列表显示成功但文件只写了一半的状态。
- 下载完整性按可用长度、下载结果及校验信息判断，保留离线任务应验证可识别的音频格式；完整 HTTP 响应不必然证明不是试听，存在可判断的片段限制时显示实际范围。
- 启动时校对记录与文件，索引损坏可从记录重建；损坏的文件不继续显示为可播放。保留意图可以保留为待修复记录。
- 清理、取消、升级和入库均由同一管理器协调，防止清空期间任务结束后又偷偷重新生成自动缓存。
- 空间不足、网络中断、崩溃不会覆盖已有有效版本；未完成临时文件按活动任务引用清理。

## 9. 存储与模块建议

新增共享的 `internal/offline` 模块，由它统一管理歌曲记录、音频版本、封面/歌词资料、保留状态、任务、容量和资源使用引用。

建议组织：

```text
应用数据目录/
  media/
    records/        # 带格式版本的歌曲记录
    audio/          # 完整音频，按记录与实际音质管理
    artwork/        # 按内容去重的封面图片
    lyrics/         # 含逐字与翻译的歌词资料
    tasks/          # 可恢复的任务信息
    temp/           # 未发布的下载
    index.json      # 可从记录重建的浏览索引
```

第一版采用版本化记录文件与可重建索引，不为该功能强制引入数据库。磁盘操作放在后台，浏览读取只读快照，避免卡住界面；写入统一串行协调并原子替换。数据规模增大后再按实际性能决定是否调整索引方案。

模块职责：

- `internal/offline`：资料持久化、查询、保存策略和任务协调。
- `internal/player`：本地优先解析、队列引用、桌面/原生播放、播放期间文件引用。
- `internal/app`：全局入口、列表与详情、批量操作、任务与设置，以及插件移除交互。
- `internal/music` / `internal/lyrics`：复用共用模型与歌词协议，必要时补充本地引用。
- `internal/plugin`：继续负责在线取资源，不负责离线资料的生命周期。
- `internal/local`：原本本地文件管理保留，避免把应用管理的缓存反复导入扫描。

使用管理器提供的本地资源描述作为两个播放器的共同输入。原来源身份用于在线操作，本地记录引用用于本机播放，不能为了播放随意把原来源改成 `local` 而丢失关联。

## 10. 桌面与安卓

三平台共享数据规则、页面含义和任务状态，音频输出沿用各自现有实现。

- macOS / Windows：将现有边下载边解码逻辑接入统一任务和存储；完整文件播放不依赖插件对象。特别验证 Windows 的文件占用、替换与删除时机。
- Android：完整文件交给现有系统播放器读取应用私有目录，歌词和封面走同一套本地资料。
- Android 在线自动缓存不能简单再开一次相同下载。需要让播放与保存共用一个下载任务，通过可支持范围读取的本机转发层为 MediaPlayer 提供数据；该层负责已下载范围、等待、拖动、取消与连接关闭。
- 若资源或设备不支持边下载边播放的这条路径，明确采用先下载再播放的降级或暂不形成自动缓存；“保留离线”仍通过完整下载任务支持。不能把系统 MediaPlayer 的临时缓冲当成应用完整缓存。
- Android 自动缓存需提供仅 Wi-Fi 的默认策略；保留离线在移动网络下先等待，用户可以对当前任务明确允许。实现时检查连接类型获取能力，不能靠是否连通推断 Wi-Fi，也不能默认重复消耗流量。
- 应用卸载或清除应用数据会删除应用私有存储中的保留离线内容；它不是跨设备备份。

## 11. 旧缓存迁移

旧音频保留，不要求用户清空重下。升级后执行可恢复、幂等的索引补建，原文件在验证与记录写入成功前不删除。

1. 识别现有 `songs/` 中完整音频与 `.json`，默认归为自动缓存。
2. 从应用已有播放会话和可用歌曲记录匹配哈希，补回原来源 ID、歌曲 ID和歌曲信息；也可读取文件已有标签。
3. 无法匹配的哈希不可逆，不能承诺找回全部歌名。此类音频作为“未识别的历史缓存”展示，保留格式、大小和音质，仍可独立播放与保留离线。
4. 原来源以后再次返回相同歌曲时，可按旧哈希补全关联，不能仅凭相同标题猜测。
5. 歌词、封面本来未保存的，只能在来源仍可用且网络允许时补充；插件已移除时显示缺失。
6. 旧文件可先由新记录引用，之后在同一文件系统安全迁移；索引建立失败可以重试，迁移期间不得让旧清理器误删新管理器接管的文件。

## 13. 验收清单

自动化使用仓库统一安静入口，测试数据全部在临时目录，网络使用本地模拟服务。关注行为与边界，不依赖真实个人缓存或真实酷狗账号。

| 场景 | 期望 |
| --- | --- |
| 歌曲完整缓存后切换插件 | 全局列表仍可见，播放与资料不受影响 |
| 移除正在播放完整本地歌曲的插件 | 当前歌曲不中断，队列不被整体清空 |
| 全部插件不可用并重启、断网 | 可浏览、搜索、恢复队列，播放全部本地歌曲；插件请求次数为零 |
| 退出账号、模拟会员资源失效 | 已存内容继续可用；新下载如实报告服务拒绝 |
| 自动缓存转保留离线 | 复用文件，不再次请求音频 |
| 缓存超限或清空自动缓存 | 只删除可淘汰内容，保留离线音频及引用资料完整 |
| 关闭自动缓存 | 不新增自动缓存，现有内容仍可浏览、保留任务可继续使用 |
| 歌词缺失或封面下载失败 | 音频可以成功入库与播放，显示准确缺失状态 |
| 逐字、翻译歌词离线重开 | 时间与文字效果保持，不退化成纯文本 |
| 同曲升级音质失败 | 旧音频仍可播放，实际音质标记正确 |
| 不同插件使用相同歌曲/专辑 ID | 不串音频、不串歌词封面、不误合并 |
| 同曲播放、预取与保留同时发生 | 复用任务，取消一个使用者不会误停另一个 |
| 下载中断、磁盘满、退出或崩溃 | 半成品不显示成功，不覆盖旧文件，可恢复或明确重试 |
| 清空与入库、删除与播放同时发生 | 不复活已清理内容，不损坏活动播放，不误删保留歌曲 |
| 旧缓存迁移重复执行或中途退出 | 文件不丢失、不重复入库，未识别音频仍可见可播放 |
| 安卓读取本地资源与拖动 | 不向原来源发请求，系统播放器接入符合文件生命周期 |

实际实施后按变更范围运行 `go run scripts/test-quiet.go` 的相关目录与用例，必要时执行三平台静态检查；不自动启动真实应用或设备。

人工验收覆盖 macOS/Windows 的真实音频与媒体信息、Windows 文件占用行为、Android 本地文件播放及范围拖动、后台/熄屏播放、网络切换与系统终止恢复。未经实际验收的项目不能写成通过。

## 14. 第一版边界

第一版包含完整歌曲的本机保存、自动缓存与保留离线、独立浏览播放、歌词封面、下载任务、清理与迁移。云同步、跨设备备份、音频标签写回、导出、跨来源自建歌单和线上歌单持续同步不纳入第一版。

保留离线表达“不会被应用自动淘汰”，不承诺文件被手动删除、磁盘损坏或应用卸载后仍然存在。
